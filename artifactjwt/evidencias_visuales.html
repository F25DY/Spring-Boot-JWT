Evidencias y Ejecución Práctica: JWT con Spring Boot 3 & MySQL

Panel de visualización interactivo de las pruebas de registro, autenticación, persistencia con BCrypt, y protección perimetral de endpoints conforme a las especificaciones del taller.

1. Registro Exitoso de Usuario
HTTP 201 CREATED
Validación de entrada: Se envía un payload con username de longitud válida y contraseña mínima de 8 caracteres. El servicio comprueba la inexistencia de duplicados y persiste el registro en MySQL.
IntelliJ HTTP Client • requests.http
### Registrar nuevo estudiante
POST http://localhost:8080/api/auth/register
Content-Type: application/json

{
  "username": "estudiante1",
  "password": "ClaveSegura123!"
}

HTTP/1.1 201 Created
Content-Type: application/json
{
  "message": "Usuario creado exitosamente"
}
2. Verificación de Persistencia y Hashing BCrypt en MySQL
SQL VERIFIED
Por qué no aparece la contraseña original: BCrypt aplica un algoritmo de derivación de claves irreversible con 1024 rondas (factor 10) y salting criptográfico de 128 bits embebido en la cadena, neutralizando ataques de diccionario y Rainbow Tables.
MySQL Workbench • jwt_demo query console
-- Consulta directa de auditoría de seguridad
SELECT id, username, password FROM jwt_demo.app_user;

3. Intento de Registro Duplicado
HTTP 409 CONFLICT
Protección de unicidad: El método UserRepository.existsByUsername() detecta la existencia previa del usuario y retorna un conflicto semántico antes de violar la restricción UNIQUE de MySQL.
IntelliJ HTTP Client • requests.http
### Reenviar exactamente el mismo registro
POST http://localhost:8080/api/auth/register
Content-Type: application/json

{
  "username": "estudiante1",
  "password": "ClaveSegura123!"
}

HTTP/1.1 409 Conflict
{
  "error": "Usuario Existente"
}
4. Autenticación y Generación de Token JWT
HTTP 200 OK
Firma HMAC-SHA256: Tras validar credenciales con AuthenticationManager, TokenService genera el token con algoritmo HS256, emisor jwtmysql-lab y validez temporal.

5. Rechazo ante Contraseña Incorrecta
HTTP 401 UNAUTHORIZED
Protección ante credenciales inválidas: Al no coincidir el hash de entrada contra el hash almacenado, se dispara BadCredentialsException y se rechaza la emisión de credenciales.
IntelliJ HTTP Client • requests.http
### Intento con credencial incorrecta
POST http://localhost:8080/api/auth/token
Content-Type: application/json

{
  "username": "estudiante1",
  "password": "PasswordErroneo999"
}

HTTP/1.1 401 Unauthorized
{
  "status": 401,
  "error": "Unauthorized",
  "message": "Bad credentials"
}
6. Acceso a Endpoint Protegido sin Token
HTTP 401 UNAUTHORIZED
Filtro de seguridad por defecto: La regla .anyRequest().authenticated() bloquea la petición antes de que llegue a SecuredController al no encontrar cabecera Bearer.
IntelliJ HTTP Client • requests.http
### Sin cabecera Authorization
GET http://localhost:8080/api/secured

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
7. Acceso a Endpoint Protegido con Bearer Token
HTTP 200 OK
Validación de identidad: NimbusJwtDecoder valida la firma HS256, extrae los claims y llena el SecurityContext, permitiendo a SecuredController devolver el nombre de usuario autenticado.
IntelliJ HTTP Client • requests.http
### Con cabecera de portador válida
GET http://localhost:8080/api/secured
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

HTTP/1.1 200 OK
Content-Type: application/json
{
  "message": "Acceso autorizado",
  "username": "estudiante1"
}
8. Detección de Modificación Maliciosa (Tampering)
HTTP 401 INVALID SIGNATURE
Protección de integridad: Si un atacante altera un solo carácter del payload o firma, el decodificador detecta la falta de coincidencia en el hash HMAC y rechaza la petición de inmediato.
IntelliJ HTTP Client • requests.http
### Token con firma alterada
GET http://localhost:8080/api/secured
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.FIRMA_MANIPULADA

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer error="invalid_token", error_description="Signed JWT rejected: Invalid signature"
9. Expiración Temporal del Token JWT
HTTP 401 EXPIRED
Validación temporal (Claim exp): Al expirar el tiempo de validez fijado (60 segundos para pruebas), Spring Security invalida el token forzando una nueva autenticación.
IntelliJ HTTP Client • requests.http
### Token tras cumplirse el tiempo de expiración (60 segundos)
GET http://localhost:8080/api/secured
Authorization: Bearer eyJhbGciOiJIUzI1Ni...

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer error="invalid_token", error_description="Jwt expired at ..."
